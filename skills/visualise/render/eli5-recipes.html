visualise · ELI5 recipes

Draw it. Then label it.

Pick the recipe that matches the shape of the idea. One metaphor family per page: choose it once (a school, a kitchen, an airport, a post office, a building site) and reuse the same characters in every panel. Real names never go in the caption; they go in chips under the figure.

1. Flow — something moves through steps

Use for pipelines, request paths, deploy sequences, "first this, then that". Highlight the step the section is about with .hot.

Use for validation chains, permission rungs, fallbacks, precedence rules. One rung per check, a verdict badge on the right.

3. Split — two things that differ

Use for old vs new design, two environments, two code paths, "shared" vs "dedicated". Highlight the one the plan chooses.

4. Before / After — one thing changes

Use for bug fixes, behaviour changes, migrations. Same scene twice; only the changed part differs.

5. Gate — who gets through

Use for auth, permissions, approvals, whitelists. A person, a door, a verdict.

6. Parts — what something is made of

Use for architecture overviews, a struct's fields, the pieces of a feature. One card per part, big emoji, three-word label.

7. Nest — what lives inside what

Use for ownership, tenancy, containers, "a group holds many policies". Boxes inside a box.

8. Count — how many, how much

Use for quantities and proportions: dots for counts (highlighted share in accent), a timeline for when things happen.

Rules that apply to every recipe

  • One figure per panel. If you need two, the section is doing two things; split it.
  • Caption is one sentence and plain words. No file names, flags, or acronyms in it.
  • Emoji are 28px or larger and are the picture. Never use them inline in body text.
  • Highlight exactly one element with the accent: the step, the option, the room this section is about.
  • If a Mermaid diagram already appears in the section, the ELI5 panel still gets its own tiny picture; it explains the idea, not the diagram.
