Recap·Phase 2·Split-tree pane layout

Panes now split where you point

The reading area used to be rows of panes, at most three by two. It is now a tree of splits, like a floor plan: put a wall up in one room and only that room is divided. Split, drop, resize and keyboard moves all follow the same rules, and closing a pane can be undone. The one cost: layouts saved by the old grid are thrown away and laid out fresh.

Built from web/layout/, web/state/workspaces.ts, web/state/store.ts and web/styles/panes.css. Numbers from wc -l web/layout/* web/state/workspaces.ts and npx vitest run web/layout. The old grid's behaviour is taken from the phase plan; its code is not in this repository.

Deviations and follow-ups

Old saved layouts are dropped, not converted

The first visit after upgrading starts fresh. Every workspace is laid out again from its docs, once.

Deviation:

Saved layouts are checked when they load. Anything that is not a pane tree, including the old grid's { rows, heights } shape, is thrown away, and the workspace is seeded from its docs as if it were new. The reason for not converting is not recorded.

The check that drops them model.ts:325–336 
export function isLayout(value: unknown): value is Layout {  const v = value as Node | null  if (!v || typeof v !== 'object' || typeof v.id !== 'string') return false  if (v.type === 'pane') return Array.isArray(v.tabs) && v.tabs.every((t) => typeof t === 'string')  return (    v.type === 'split' &&    (v.dir === 'row' || v.dir === 'col') &&    Array.isArray(v.children) &&    v.children.length === v.sizes?.length &&    v.sizes.every((s) => Number.isFinite(s) && s > 0) &&    v.children.every(isLayout)  )
deviated
Old layouts are dropped and re-seeded. store.ts:48–51 · workspaces.ts:56–61

The store filters saved layouts through isLayout on load; entering a workspace with nothing saved calls seed. Cost: one lost arrangement per workspace per browser.

kept
Six panes is now a starting point, not a limit. model.ts:21–24 · model.ts:198–205

seed still lays out at most six panes on a first visit. After that, a split is allowed whenever both halves stay at least 280px wide or 180px tall.

follow-up
The hands-on parts have no tests. PaneView.tsx · TabStrip.tsx · SplitView.tsx

Drop preview, middle-click, the Undo toast and divider dragging were not covered by automated tests in this phase. Seen in the code, not listed in the plan.
